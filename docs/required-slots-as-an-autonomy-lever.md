# Required slots as an autonomy lever

**Written 2026-09-18, at the operator's direction, as a reference for future
work.** The observation is theirs: that this is mechanizable is interesting on
its own, and it looks like a path to more autonomy across a multitude of
areas rather than one fix.

> **WIDENED 2026-09-19: this is a PILLAR, not a clever trick.** `docs/purpose.md`
> names three legs the environment supplies — PRESENCE, DEMAND, and INDEPENDENT
> FEEDBACK — and this document is the canonical carrier of the DEMAND leg. The
> reason it is load-bearing rather than merely useful: presence alone measurably
> under-fires (the adherence split — rules loaded the whole session and inert in
> 5 of 6 corrections), so putting the right state in view does not by itself make
> it engage. A required slot converts "should engage" into "cannot proceed
> without engaging", which is the only conversion that survives momentum. Read
> this file as one third of the creed, with `docs/purpose.md` as the north star.

## The pattern

**Do not ask an agent to decide well. Require it to WRITE something at the
moment of deciding.** The writing forces the thinking; the slot's presence is
computable; the quality of the fill stays judgment.

This is distinct from the capture mechanisms in `answerable-not-felt.md`.
Those persist what happened. **This one changes the decision as it is made**,
because articulating a thing is not free — you cannot write "why this is not
derivable" without checking whether it is.

**Why it clears the mechanism bar** where a prose rule does not: the trigger
is a computable predicate (is the slot filled?) with near-zero false fires,
and the failure mode of a duty — under-firing while loaded — does not apply,
because the work cannot proceed without the fill.

## Measured instances, 2026-09-18 — all in one day, all the same shape

| the refusal | what it forced |
|---|---|
| `--absence` on `item add --join new` | a peer desk wrote a substantive fact — an operator mid-capture with instruments on a live game — which they report they would NOT have written unprompted |
| the one-file one-hunk cost test | a peer dropped a booking and built the thing instead; the entry would have cost what the fix cost |
| `blocker_unstorable` (300-char cap) | a 477-char decision question rephrased into one that could actually be ANSWERED, since decision blockers resolve by question-slot equality |
| the intake join | disposition against candidate duplicates the booker had not considered |
| the drop-reason cap | the reasoning moved onto the entry body, where it will be read, instead of into a ledger line that truncates it |

**None of these is a rule anyone remembered. Each is a slot that had to be
filled before the work could continue.**

## The candidate list — existing prose rules with no slot

Measured this same day: the operator corpus carries **27 `Convention:`
statements and roughly 5 carry a token**. The tokened ones fire; the rest are
duties. Each of the following is an existing rule whose firing moment is
known and whose slot does not exist:

1. **An ABSENCE claim names its positive control.** The highest-value one.
   A zero-hit search, a clean scan, a "nothing found" — each returns exactly
   what a dead instrument returns. **This class bit this desk four times in
   one day**: an extractor returning 0 for a full file, a journal enumeration
   off by 7.6x, a missed `ledger.py` write site, and a roster red read from a
   mutation window. Every one a zero believed without a known positive.
2. **A DECISION blocker names why it is not derivable** — booked as lc-169,
   the instance that prompted this document.
3. **A VERDICT names what would flip it** — the discriminating probe. The
   corpus requires it; nothing demands it be written.
4. **A DECLINE names which of the three grounds it stands on** (duplicate
   home, no incident, wrong truth-level). Stated and unwritten, the closed set
   is a pledge.
5. **A HOLD names the EVENT that lifts it**, never a time-word, because
   "later" re-enters only by memory.
6. **A COMPLETENESS claim names the enumeration it was checked against.**
7. **A relayed FIGURE names whether it is machine-computed or an estimate.**

## Why this is an autonomy lever specifically

**It moves work from the operator's column to the desk's without asking the
desk to be more careful.** The kind split says operator attention neither
scales nor parallelizes; a slot that forces derivability-checking BEFORE a
question travels is the mechanism that keeps derivable questions from
travelling at all.

And it is the retirement path the payoff section describes, from the other
end: **a prose convention converted into a required slot at its firing moment
is a convention that fires.** The corpus can then retire the prose, because
the duty is discharged by construction rather than by memory.

## The boundary

**The slot demands the STATEMENT, never the answer.** A genuinely undecidable
question — intent, preference, authority over the irreversible — states that
in one line and passes. A slot that tried to decide what is constitutively
the operator's would be the over-constraint this whole arc argues against.

**And the fill's QUALITY is not computable.** A slot filled with nonsense
passes the check. What the slot buys is that the thinking happened at the
moment it was cheapest, and that its absence is visible at a glance — which
is the whole of what a mechanism can do here.
