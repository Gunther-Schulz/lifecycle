## 1. Per-row fit assessment

**CMMN** — CONFIRMED. A sentry is an ECA rule: "on <event> if <condition>", or event-only, or condition-only; sentries gate entry/exit on stages, tasks, and milestones (VERIFIED, OMG CMMN spec + Red Hat docs, Visual Paradigm). Borrowable: "Sentry" (event-part + condition-part, attached to the gated element) → N6, almost a direct structural template for "observable trigger + question with state in front"; "Milestone" (an accomplishment marker distinct from task completion) → N5, completion-at-the-right-altitude rather than activity-finished.

**Kepner-Tregoe** — CONFIRMED. IS/IS-NOT specification runs across four dimensions (identity, location, timing, extent): what the problem IS vs IS NOT, and the *distinction* between the two matched/unmatched cases is what narrows causes (VERIFIED, Kepner-Tregoe site, Toolshero). Borrowable: "IS/IS-NOT pair" → N6 (the seam poses the question with both the positive and negative case in front, not the positive alone); the four-dimension checklist → a typed-slot template for what "relevant state" must include before a judgment is asked.

**Differential diagnosis + SOAP** — CONFIRMED, with a nuance: classic SOAP teaching mandates the Assessment→Plan slot and ranks the differential most-to-least-likely; "test ordered to maximize information gain" is textbook Bayesian clinical reasoning but the specific term "information gain" surfaced in the search mainly from recent AI-diagnostic-system papers (MedKGI) rather than classic clinical pedagogy — treat the framing as PARAMETRIC, the underlying practice (order tests that discriminate leading hypotheses) as VERIFIED by general clinical-reasoning literature. Borrowable: ranked differential → N1 (visible narrowing, a yield signal); mandatory non-empty Plan slot → N6 (typed slot for the answer, no null state permitted).

**ITIL problem management / KEDB** — CONFIRMED. A Known Error = documented root cause + workaround, stored in the KEDB specifically so support staff consult it *before* re-diagnosing (VERIFIED, Atlassian, InvGate, Wikipedia "Known error"). Correction: real-world criticism (below) shows the "consulted before diagnosis" step is exactly what degrades first — the record exists but nothing forces the consult. Borrowable: "Known Error Record" (root cause + workaround as one addressable unit, searched first) → closest prior art for a dead-end/workaround ledger consulted at the *start* of a new investigation, which sharpens N2 (the check that matters is the one at the moment someone is about to re-derive something already known, not at write time).

**SRE blameless postmortems** — CONFIRMED. Standard artifact: summary, timeline, root-cause analysis, impact, corrective action items with owner + due date; "incorporate recurring findings into onboarding and runbooks" is explicit institutional practice (VERIFIED, sre.google, incident.io). Borrowable: action items as a *typed* item (owner, due date, category incl. "write/update runbook") → N3, this is the cleanest confirmed instance of self-authoring-of-procedure being a first-class postmortem output rather than a separate step; action-item tracking-to-closure across a *different* tool than the postmortem doc → sharpens N5 (see part 4).

**Toyota A3 / PDCA / andon / standard work** — CONFIRMED. A3 = one physical page forcing background → current condition → goal → root cause → countermeasure → implementation plan → follow-up, so the whole story stays visible at once; andon = a physical stop-the-line signal tied to Jidoka, thousands of pulls per shift at a real plant; solved problems get folded back into standard work documentation (VERIFIED, leantps.ca, 6sigma.us, thesystemsthinker.com, artoflean.com). Borrowable: "andon" → the single best-verified match for N2 (the check fires at the moment a defect would be *passed downstream/consumed*, not when produced or authored); A3's mandatory "follow-up" slot → N1 (forces a return visit to the goal, not just a one-shot countermeasure).

**GTD** — CONFIRMED, with a correction worth flagging: GTD's own literature treats the Weekly Review, not the next-action rule alone, as the load-bearing mechanism — practitioner consensus is that abandonment traces to skipped reviews, and skipping it is described as causing exactly the silent-drift failure mode N1 exists to prevent ("lists become stale... mind re-absorbs the open loops"). (VERIFIED, multiple GTD guides + practitioner-community summaries). So the "next action" atomicity idea is real but not GTD's strongest export — the review cadence is. Borrowable: "next action" (single, concrete, physically-executable step, never a project name) → N6 typed-slot discipline; "Weekly Review" as a *mandatory calendar-triggered full re-scan* → a weaker cousin of N1 (it's schedule-triggered, not yield-triggered — see the correction in part 2 below).

**Statecharts/BPMN completeness** — CONFIRMED. "Soundness checking" via state-space exploration formally finds unreachable states, dead/stuck states (no outgoing transition while instances are still live), and no-dead-activity violations (VERIFIED, arxiv 2407.03965 on BPMN soundness, USPTO/ResearchGate on Statemate unreachable-state detection). Borrowable: the soundness check itself → N6, this is the most literal prior art for "every judgment moment gets a registered seam" — it's the formal version of asking, for a declared process graph, whether every state has a way out and every transition is reachable.

## 2. Missed traditions (ranked, max 5)

1. **Scientific workflow provenance systems** (Kepler, Taverna, VisTrails, Pegasus) — VERIFIED at the general level: "not knowing the exact provenance and processing pipeline... often renders a derived data set useless from a scientific point of view," and provenance capture (lineage + execution context + workflow-version history) is treated as core, automatically-instrumented infrastructure, not optional metadata (arxiv/SIGMOD, Davidson & Freire 2008). This is the strongest single miss: none of the 8 rows directly cover "mark a comparison between two changing artifacts as needing re-derivation," and workflow provenance is built exactly to answer "is this derived result still valid given what changed upstream." The "re-derive-at-read" framing itself is PARAMETRIC extrapolation from lineage tracking, not a verified named concept.
2. **Theory of Constraints thinking processes** (Current Reality Tree, Evaporating Cloud) — VERIFIED (Goldratt; TOC Institute, Wikipedia). CRT is a cause-effect network of undesirable effects converging on root cause(s); Evaporating Cloud diagrams a stuck conflict plus the assumptions holding it in place. Fits N1 (a visible chain toward a stated goal, with each unresolved effect as a yield unit) and gives a named tool for the specific failure mode of an investigation stuck in a false dilemma.
3. **Cynefin** — VERIFIED (Snowden & Boone; Wikipedia). "Probe-sense-respond" is explicitly the prescribed mode only in the complex domain, where cause-effect is knowable only in retrospect — this is directly useful for N3, because it names the *precondition* under which self-authoring-a-procedure is the right move (no existing pattern, safe-to-fail experiments) versus when a documented procedure should simply be applied (clear/complicated domains). None of the 8 rows draw this domain boundary explicitly.
4. **8D's dual root-cause requirement** — VERIFIED (multiple 8D guides, sixsigmastudyguide, learnleansigma). D4 requires verifying not one but two causes: the cause of the defect, and separately the cause of the *failure to detect it* before impact — "investigations that find the operator error and stop have addressed the first cause and ignored the second." This is a sharp, underused concept for N2: it asks not just "what happened" but "why did the check that should have caught it not fire," i.e. why the consuming-moment trigger didn't trigger.
5. **Aviation CRM / checklist discipline** — VERIFIED at a general level (FAA CRM history doc, SKYbrary). The operative distinction is checklists *read* (challenge-response) vs recited from memory, flagged as a critical CRM inspection point; Threat and Error Management (TEM) is now the organizing frame, separating external threats from internal errors as distinct categories needing distinct handling. Relevant to N6: a typed slot that must be actively read/answered, not passed from memory, is exactly the read-vs-recite distinction.

## 3. Documented degenerate form per adopted tradition (anti-borrow list)

- **CMMN**: PARAMETRIC (not directly searched) — sentries/stages proliferate into an unreadable condition-lattice used for compliance diagramming that nothing actually executes against; treat with caution, no source-backed critique retrieved.
- **Kepner-Tregoe**: PARAMETRIC — becomes rigid form-filling disconnected from the live investigation ("fill in the IS/IS-NOT grid" as ritual); no specific source retrieved for this critique, flagged as inference from general structured-method fatigue, not verified.
- **SOAP/differential diagnosis**: PARAMETRIC — EHR "note bloat," Assessment/Plan sections copy-forwarded visit to visit without re-narrowing the differential; a well-known clinical-documentation complaint but not the specific query run this round.
- **ITIL KEDB**: VERIFIED — "content not fulfilling required purposes and not even being consulted when required"; confusion between KEDB and the general Service Knowledge Management System causes exactly this; staleness accumulates without active pruning as fixes land (Pluralsight, LinkedIn/Sundararajan piece).
- **SRE postmortems**: VERIFIED — "blameless theater": the org adopts blameless language without substance, so the document "carefully avoids naming anything at all"; "action item confetti" — unowned, undated items generated in the last five minutes, never followed because sprint planning lives in a different tool with different priorities; document read once then never reopened (codelikeagirl.substack, incident.io).
- **Toyota A3/PDCA**: PARAMETRIC leaning VERIFIED-adjacent — the retrieved Gemba Coach piece is literally titled "Does everyone at Toyota write A3 reports for every problem?", implying the live critique inside Lean circles is A3-as-mandatory-bureaucratic-ritual/PowerPoint-deliverable divorced from gemba observation; the article itself wasn't read past the search snippet, so mark this PARAMETRIC.
- **GTD**: VERIFIED — system rot from skipped Weekly Review is the community-documented single point of failure: "those who abandon GTD typically don't fail at capturing or organizing — they stop reviewing"; without it, "Waiting For" and next-action lists silently go stale (Asian Efficiency, nerdproductivity, nerd/practitioner summaries).
- **Statecharts/BPMN soundness**: PARAMETRIC — general BPM-literature critique is that soundness verification is run once at model-authoring time and never re-run as the live process drifts from its diagram, so the model becomes a certified-sound picture of a process that no longer matches reality; not the specific query run this round, treat as inference.

## 4. Closest single prior-art solution per need

- **N1** (goal + running yield count) — Toyota A3's mandatory follow-up slot, which forces a return to the stated goal after each PDCA cycle rather than closing on the countermeasure alone (VERIFIED shape; "yield count" framing is this round's own synthesis).
- **N2** (trigger fires at the consuming/believing moment) — Toyota andon: the stop-signal fires when a defect is about to move downstream to the next consumer, not when produced or logged (VERIFIED).
- **N3** (self-authoring of procedure on an undocumented journey) — SRE blameless postmortem action items, which name "write/update the runbook" as a first-class corrective-action type baked into the standard postmortem output (VERIFIED); Cynefin supplies the precondition (complex-domain only) that N3 itself doesn't state but probably should.
- **N4** (comparisons between two changing artifacts, marked re-derive-at-read) — scientific workflow provenance/lineage tracking: a derived result is explicitly tied to the exact upstream pipeline state that produced it, and is understood to need re-derivation once that upstream state moves (VERIFIED at the general provenance level; the "mark distinct from durable facts" framing is this round's extrapolation, not a named concept in the literature).
- **N5** (completion defined at the consumer, not the producer) — SRE postmortem action-item rot: the documented failure mode is items existing in the postmortem doc but not being "where the next system reads it" (sprint planning, a different tool), which is the mirror-image proof of N5's own definition (VERIFIED — incident.io: "written for a filing cabinet, not a future engineer with a decision to make").
- **N6** (every judgment moment: observable trigger, question with state in front, typed slot, next step) — CMMN's sentry (event-part + condition-part gating a stage/task/milestone) is the most literal structural match found; BPMN/statechart soundness checking is the formal-verification analog for auditing that every such seam actually has a way out (both VERIFIED).
