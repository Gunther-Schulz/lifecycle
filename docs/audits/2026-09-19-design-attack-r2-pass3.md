## Terra recovery arm over v3, verbatim
## Vocabulary contract

1. **BLOCKING — P3’s “forward-only door stamp” has no defined carrier shape or lifecycle.**  
   Lens: DANGLING EDGES / DEGENERATE FORMS.  
   P3 says a stamp is written at add, park, and amend, but never specifies its slot name, serialized form, reader, or removal/disposition rule ([design:66-77](docs/2026-09-19-vocabulary-contract-design.md:66)). This fails the design’s own “what must be written” law. Worse, its stated repair only orders the build specimen to re-type before the stamp lands; it does not handle the ordinary sequence: evidence blocker stamped, then amended to `external`. The stamp remains on an ineligible record.  
   Basis: reasoning from the artifact; current conditional-slot machinery selects by the item’s current blocker type ([items.py:2155-2187](plugin/cli/lifecycle_core/items.py:2155)).  
   Repair direction: define the exact stamp slot, effective-reader rule, and retype/clear disposition, then red-test the evidence→external sequence.

2. **NOTABLE — OOV “drain” has no durable, owned decision mechanism.**  
   Lens: DANGLING EDGES / STOP-YIELD.  
   The document calls accumulated reasons a widening signal through a “mint round / disposition amendment” and a “ledger,” but names neither the ledger record shape nor a reader/trigger that must decide widen versus retire ([design:109-116](docs/2026-09-19-vocabulary-contract-design.md:109)). “The printed age” is not a threshold or an actor-owned act ([design:28-37](docs/2026-09-19-vocabulary-contract-design.md:28)). The alleged existing retirement-pass pattern is only a warning: `item ratio` says a pass is owed, but records no pass and has no ledger write ([verbs.py:1592-1597](plugin/cli/lifecycle_core/verbs.py:1592)).  
   Repair direction: name the durable disposition record and its consuming pass.

3. **NOTABLE — PERISHABLE deliberately false-flags a valid same-day re-derivation.**  
   Lens: OVER-CONSTRAINT.  
   A re-derivation made after a mark but on the same date is expressly deemed “not re-derived” ([wave:28-35](docs/2026-09-19-wave-designs.md:28)). That makes the normal immediate repair appear stale until tomorrow, creating a guard that fires on legitimate work.  
   Basis: reasoning-only.  
   Repair direction: use an orderable timestamp or an explicit same-day ordering rule.

4. **BLOCKING — The claimed “zero always-on execution” is false under the document’s own definition, so lc-234’s unresolved gate is bypassed.**  
   Lens: THE EROSION BOUND / DUAL ROOT-CAUSE.  
   W1 says the banner reads the last result from the fire-log detail on every render ([wave:12-18](docs/2026-09-19-wave-designs.md:12)), while defining always-on as any unchosen running path ([contract:94-98](docs/2026-09-19-vocabulary-contract-design.md:94)). That is new always-on execution—at minimum a log read/parse/filter—not “content” alone. The inventory therefore records zero falsely ([wave:73-74](docs/2026-09-19-wave-designs.md:73)). The probe itself explicitly reaches no health verdict: one genuine regression exists and the evidence cannot decide whether it is erosion or noise ([erosion results:205-219](docs/audits/2026-09-19-erosion-probe-results.md:205)).  
   Repair direction: count the banner read as always-on and apply the stated gate before admitting it.

## ARC kinds

1. **BLOCKING — The displayed kind declarations fail the current declaration schema in multiple independent ways.**  
   Lens: FIT AND SHAPE / DANGLING EDGES.  
   Despite claiming the validator is the “author’s first reader” ([arc:9-11](docs/2026-09-19-arc-kind-design.md:9)), both objects use:
   - scalar prose `reader` values, although `reader` must be a non-empty list of typed references ([declaration.py:1169-1218](plugin/cli/lifecycle_core/declaration.py:1169));
   - `exit.detail`, while `exit.recording-act` is mandatory ([declaration.py:1235-1253](plugin/cli/lifecycle_core/declaration.py:1235));
   - `trigger: "verb:arc"`, although parser grammar recognizes a mode word `verb` followed by a separate verb name ([declaration.py:1262-1303](plugin/cli/lifecycle_core/declaration.py:1262)).  
   If implementation changes the schema to accept the shown scalar/prose forms rather than correcting them into existing forms, that is an unacknowledged declaration-schema shape change and needs its own numbered version bump/migration.  
   Repair direction: make the declaration conform to the existing typed shapes, or explicitly version and migrate the widened schema.

2. **BLOCKING — Pinned closed-arc schemas contradict the one-schema-per-repo law and have no executable exemption.**  
   Lens: FIT AND SHAPE.  
   The design says closed bodies retain their closing schema while live arcs track the repo schema ([arc:52-61](docs/2026-09-19-arc-kind-design.md:52)). But the binding law requires every carrier’s `schema:` to equal the repository declaration ([CLAUDE.md:32-38](CLAUDE.md:32)), and the current agreement checker has no record exemption ([declaration.py:1974-2002](plugin/cli/lifecycle_core/declaration.py:1974)). The claimed “closed kind exemption” is prose, not a validator rule.  
   Repair direction: reconcile the law, carrier definition, and executable checker in one versioned migration decision.

3. **BLOCKING — Conservation’s denominator cannot express its declared baseline.**  
   Lens: THE REPAIR IS WHERE THE CLASS SURVIVES / DEGENERATE FORMS.  
   `INDEX.md` is declared to carry `baseline/opened/closed`, but its invariant is only `opened − closed = live` and `closed = closed files` ([arc:40-46](docs/2026-09-19-arc-kind-design.md:40)). Baseline is neither consumed nor included in the live-count equation. Any migrated/pre-existing population makes the counters either wrong immediately or renders `baseline` dead data. No listed reader/check validates INDEX at a later moment.  
   Basis: reasoning-only.  
   Repair direction: define one conservation equation and an executable reader that consumes every counter.

4. **NOTABLE — The claimed stop/yield is absent from the locked artifact.**  
   Lens: STOP/YIELD.  
   The final section merely says “v2’s” conditions are unchanged and relocates an inventory line ([arc:133-135](docs/2026-09-19-arc-kind-design.md:133)); it gives no stop condition, yield payload, actor, or computable trigger. “STOP renders at entry” is an output claim, not a condition ([arc:73-75](docs/2026-09-19-arc-kind-design.md:73)).  
   Repair direction: state the actual stop/yield contract in this locked version.

5. **NOTABLE — The purpose’s arbitrary-moment kill test is knowingly left unmet without a bounded disposition.**  
   Lens: FIT AND SHAPE / DUAL ROOT-CAUSE.  
   The design admits that a verdict heard before `arc verdict` is lost if the session dies ([arc:97-106](docs/2026-09-19-arc-kind-design.md:97)). That is precisely a load-bearing state existing only in a head, contrary to the north star’s “every act writes its state as a byproduct” ([purpose:41-56](docs/purpose.md:41)). “Pilot watches latency it can see” cannot observe the events that were never recorded.  
   Repair direction: either make the claimed kill-test scope honest or introduce a detectable disposition for unrecorded event-to-verb gaps.

## Wave mechanisms

1. **BLOCKING — W1’s supposed retirement-pass consumer does not exist.**  
   Lens: DANGLING EDGES / DUAL ROOT-CAUSE.  
   W1 and W2 both claim that, when “pass owed” prints, a retirement pass writes a ledger note grading their catches ([wave:19-22](docs/2026-09-19-wave-designs.md:19), [wave:38-40](docs/2026-09-19-wave-designs.md:38)). Current code only prints an instruction that a pass is owed ([verbs.py:1592-1597](plugin/cli/lifecycle_core/verbs.py:1592)); there is no pass verb or ledger-note writer/reader. Thus both mechanisms terminate in prose exactly where the repair claims ownership.  
   Repair direction: name and implement the pass record and its reader before relying on it as the no-yield disposition.

2. **NOTABLE — W1’s result carrier is machine-local, best-effort, and does not travel with the project.**  
   Lens: DEGENERATE FORMS / FIT AND SHAPE.  
   The fire log is explicitly XDG-local, append-only, and allowed to lose writes ([firelog.py:1-23](plugin/cli/lifecycle_core/firelog.py:1)). W1 uses it as the only last-run carrier ([wave:12-18](docs/2026-09-19-wave-designs.md:12)). A fresh session in another clone/machine has no project-persisted evaluation result, defeating the stated continuous-project-mind intent.  
   Repair direction: make the status’s authoritative state project-scoped, or explicitly limit the mechanism’s continuity claim.

3. **NOTABLE — W3’s “registered executable Python” population is not mechanically defined enough to be a continuing reach contract.**  
   Lens: DEGENERATE FORMS.  
   “Shebang-or-extension” does not define Python: an extensionless shell hook has a shebang but is not Python; a `.py` file need not be executable; and arbitrary kind homes can be files, globs, or directories. The existing scanner indeed only visits `*.py` under `CORE` ([roster.py:97-121](plugin/cli/lifecycle_core/roster.py:97)), confirming the old blind spot but not supplying a new precise population predicate.  
   Repair direction: specify one testable executable-Python classifier and its behavior for every legal home shape.
